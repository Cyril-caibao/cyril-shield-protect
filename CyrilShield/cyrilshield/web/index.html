CyrilShield

一个本地运行的程序加固工具箱：拆图标、UPX 压缩、虚拟机壳保护、APK 加固。全部处理都在本机完成，不上传任何文件。

APK 加固做了什么
  • 解析二进制 AndroidManifest，把 android:name 指向随机命名的壳类（字符串池与资源映射保持原索引，只追加不改动）。
  • 抽取全部 classes*.dex，逐文件用 HMAC-SHA256 计数器流加密，塞进随机命名的 assets 路径。
  • 载荷无固定头部：密文直接开头，nonce 与校验码附在尾部，任意一位被改写都会在解密前被拒。
  • 壳在 attachBaseContext 解密并注入自身 ClassLoader 的 dexElements；Android 8.0+ 直接内存加载，明文 dex 不落盘。
  • 真实 Application 通过 Instrumentation 重建并接管框架侧实例，getApplication() 仍返回你原来的类。
  • 密钥分片拆成八组常量，前四组与后四组异或后才成形，再过两级 HMAC 派生每段子密钥；类名、包名、资产路径每次构建随机。
  • 重打包后 zipalign 4 字节对齐并重新签名（minSdk < 24 自动补 v1 签名），签名别名随机，产物里不留固定字符串。
VM 虚拟壳做了什么
  • 目标程序以计数器流密钥加密存为载荷，元数据单独加密。
  • 一段随机生成的字节码驱动内置虚拟机：重建密钥 → 分块解密 → 校验 → 释放运行。
  • 每次构建的魔数、盐、分块大小、操作码、指令字段排列、立即数混淆、符号名全不相同。
  • 字节码与载荷各有 SHA-256 摘要，被改写即拒绝运行。

便携版把精简 JRE（含 javac / keytool）、build-tools 的 d8 / apksigner / zipalign 与 android.jar 一起打进程序，目标机器不需要安装 JDK 或 Android SDK，拷贝单个文件即可完成 APK 加固；体积因此约为普通版的四倍。VM 虚拟壳仍需要系统中的 Python + PyInstaller 才能编译外壳。

本工具用于保护你拥有合法权利的程序；APK 加固同理，只处理你自己的应用。壳只做「加密 + 完整性 + 虚拟化执行 + 类加载注入」，不含反调试、反沙箱、杀软对抗、AMSI 绕过或进程注入。加壳会使数字签名失效，发布前请自行重新签名；第三方应用商店/加固检测可能对「dex 被抽空」这一特征报警，这是抽取式加固的固有代价。
